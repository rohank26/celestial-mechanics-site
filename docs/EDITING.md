# Editing the site

## Words and photos (no code)

1. Open `/keystatic` on the live site and sign in with Keystatic Cloud (see [DEPLOY.md § 2](DEPLOY.md#2-turn-on-the-cms-one-time)).
2. Under **Pages** in the sidebar, each page of the site has its own entry, plus **Header and footer**, **Signature configurations** and **Commission (builder and enquiry form)**.
3. Change any text, swap a photo, then click **Save**. The CMS saves your change to GitHub and Cloudflare rebuilds the site; it's live in about two minutes.

To change several pages and publish them together, use a draft: in the CMS's branch menu (it shows **main**) choose **New branch**; saves go to `draft/<name>` and stay off the live site until you click **Create pull request** and merge it on GitHub.

## The builder and the drawings

- **Options** (system, planet size, material, mechanism, sun, add-ons and the rules between them, e.g. Aurora adds the Planetary Controller and the Pavilion is outdoor-only) are defined once in `src/cm/options.ts`. Their names and descriptions come from the CMS, so renaming an option needs no code; adding a brand-new option means adding its id there and its wording in the CMS.
- **Drawings** are generated, not uploaded: `src/cm/drawing.ts` draws any configuration in plan and elevation in the engraved brass style. The builder, the signature configurations, the audience pages and the add-ons page all use it, so they always agree.
- **Signature configurations** are edited in the CMS (**Signature configurations**). Each card's "Start from this" opens the builder with that configuration; their drawings update on their own. Each audience page features one, chosen in that page's **Starting point**.
- **Shareable sketches:** the builder keeps the sketch in the address (`/commission/?c=0221001010`), so a link reopens it exactly. `?for=residence|institution|business` preselects who the enquiry is for (the audience pages link this way).

## Enquiries

The commission form posts to `/api/contact` (`src/worker/contact.ts`). Each enquiry is emailed to rohank@gmail.com with the subject **Commission enquiry: Name (Organisation)**, and includes the sketch in words plus a link that reopens it in the builder. Reply to the email to answer the person directly.

Spam is filtered quietly (a hidden field bots fill in, a minimum time to fill the form, a limit on links, and at most 5 enquiries per hour from one address); spam gets the same "thank you" so bots learn nothing. Every real enquiry is saved before it's emailed, and anything not yet sent is retried hourly (see [DEPLOY.md § 3](DEPLOY.md#3-enquiry-emails)).

## Design

The colours, type and buttons come from The Grand Orrery's design system (`src/styles/global.css`, carried over so the two sites stay one family); the studio's own components are styled in `src/styles/cm.css` and in each component. The animated sky is `src/components/SkyBackdrop.astro` and the animated orrery on the home page `src/components/OrreryDiagram.astro`, both shared with the Grand Orrery site. If either changes there, copy it here too.

## Logos

`public/brand/cm-crest.svg` (armillary sphere above the plaque) and `public/brand/cm-wordmark.svg` (the plaque alone, used in the header) are generated by `tools/logo/build_cm.py`, which reuses the Grand Orrery logo parts in `build.py` and `build2.py`. It can also draw the two alternative crests (gear and monogram):

```sh
pip install fonttools brotli uharfbuzz
mkdir fonts && cd fonts
npm pack @fontsource/cinzel @fontsource/cinzel-decorative @fontsource/pinyon-script
for f in *.tgz; do d=${f%.tgz}; mkdir -p $d && tar xzf $f -C $d; done
cd ..
FONT_DIR=fonts python3 build_cm.py out    # writes cm-crest-armillary.svg (the chosen one), -gear, -monogram and cm-wordmark.svg
```

## Editing all the copy as one text file

To review or rewrite the wording outside the CMS:

```sh
npx tsx tools/copy/copy.mts export copy.txt    # every piece of copy, page by page
npx tsx tools/copy/copy.mts import copy.txt    # write the edited text back into src/content/cm/
```

Each piece of copy sits under a `>>` line naming where it goes. Import changes only the text, reports anything it couldn't place, and lists changes to the few texts written into the page code (form labels and the like, under "Fixed text") so they can be made by hand. Run the content check below afterwards.

## Checking content against the CMS

After changing a content file or `keystatic.cm.ts` by hand, run:

```sh
npx tsx tools/check/validate-content.mts
```

It reads each page the way the CMS does and fails if a file wouldn't open, or holds a field the CMS would drop on its next save.
